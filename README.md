# SHMUP Game - GDC Assignment Sheet

###### 🎮 Game Design Challenge | ⚙️ Game Development | ⏱️ TIMELINE: 2 Weeks

## 📖 Overview

For this **Game Design Challenge**, you will design and develop a **Prototype (Draft)** of a Shoot ’em Up (SHMUP) game that demonstrates the intended player experience through approximately **1–2 minutes of fun, playable gameplay** while meeting the design and technical requirements provided in the challenge documentation.

> [!Important]
> Review and follow the **[Game Design Challenge Guidelines](https://csg-utulsa.github.io/csg-assignments/game-design-challenges/index.html)** before beginning development.

---

## 📝 Assignment Instructions

### 1. Develop the Prototype (Draft)

1. Begin by reviewing the following challenge documentation:
   - **[Concept Document](https://github.com/CSG-3023/GDC-ShmupGame/wiki/Concept-Document)** — Establishes the game's concept, premise, theme, and creative direction.
   - **[Player Persona](https://github.com/CSG-3023/GDC-ShmupGame/wiki/Player-Persona)** — Defines the target player and their characteristics, motivations, and preferences.
   - **[Game Brief](https://github.com/CSG-3023/GDC-ShmupGame/wiki/Game-Brief)** — Defines the game's requirements, scope, and development direction.
   - **[Technical Brief](https://github.com/CSG-3023/GDC-ShmupGame/wiki/Technical-Brief)** — Defines the game's technical requirements, development tools, controls, performance targets, and software dependencies.

2. Develop a **Prototype (Draft)** that follows the requirements and creative direction established in these documents.

> [!Warning]
> Failure to follow the requirements established in the above documents may result in a reduced grade.

---

### 2. Build and Publish the Game

1. Create and test a **WebGL build** of the completed Prototype (Draft). Ensure the game loads, plays correctly, and provides the intended experience.

2. Publish the WebGL build to **itch.io** so the game can be played directly in a web browser.
   * Follow the **[Upload to Itch.io Tutorial](https://csg-utulsa.github.io/csg-assignments/tutorials/itch-io/TU-Itch-io-Submission.html)** for the required upload and configuration process.

3. Submit your game to the **Playtest Game Jam** for peer evaluation. The link to the game jam will be provided in Harvey.
   * Follow the **[Submitting to an Itch.io Game Jam Tutorial](https://csg-utulsa.github.io/csg-assignments/tutorials/itch-io/TU-Itch-io-JamSubmission.html)** for the required upload and configuration process.

> [!NOTE]
> If you do not already have an **itch.io account**, you will need to create one. The **[Create an Itch.io Account Tutorial](https://csg-utulsa.github.io/csg-assignments/tutorials/itch-io/TU-Itch-io-Account.html)** can help guide you through the process.

> [!WARNING]
> All games must be submitted to the **Playtest Game Jam** for grading and peer evaluation. Games not submitted to the Playtest Game Jam by the deadline **WILL NOT BE GRADED**.

---
### 3. GitHub Wiki Documentation

Maintain and update your **Project Wiki** throughout development to document the game's design and development.

1. **Clone the Starter Project Wiki**
   - Follow the instructions provided in Harvey to clone the starter Project Wiki.
   - The starter Wiki includes the required project documentation pages and templates.
  
2. **Define the Creative Direction**
   - Complete the **Creative Direction** section of the Concept Document.
   - Define:
     - **Premise:** What is the game about? What is happening, and what is the player's purpose?
     - **Setting / Theme:** Where does the game take place, and what central idea or theme shapes the experience?
     - **Art Style:** What visual style will the game use? Consider how the visuals support the premise and theme while remaining optimized for WebGL performance.
3. **Maintain the Asset List**
   - Complete the **Asset List** using the provided template.
   - Document all assets used in the project, including their source and use.
   - Update the Asset List as assets are added or changed during development.
4. **Complete the Technical Documentation**
   - Create a **Core Gameplay** page briefly describing the player's actions, challenges, feedback, progression, and objectives.
     - Include a **flowchart diagram** illustrating the core gameplay loop.
   - Create an **Objects & Entities** page identifying the major objects and entities in the game and explaining their purpose, behavior, and interactions.
5. **Create and Add a Class Diagram**
   - Follow the **[Class Diagram Tutorial](https://csg-utulsa.github.io/csg-assignments/tutorials/UML-Diagram/TU-ClassDiagram-VS.html)** to create and export the class diagram.
   - Add the exported class diagram to the appropriate page in the Project Wiki.
  
> [!IMPORTANT]
> **Target Audience and Content Restrictions**
>
> Design for an **ESRB E10+ (Everyone 10+) audience**. No lethal weapons or realistic violence; use stylized, cartoon conflict and creative, nonlethal alternatives that fit your game's premise and theme.

> [!NOTE]
> **Creative Direction vs. Implementation**
>
> The Creative Direction establishes the game's intended experience and guides your design decisions. However, **the primary grading emphasis is on gameplay functionality and working mechanics, not visual polish or narrative depth**. Focus on creating a playable prototype that demonstrates your core gameplay loop and interactive systems. Visuals and theme should support the intended experience but do not need to be fully polished.

---

### 4. Submit Your Project

Submit the following URLs:

- **itch.io:** URL to your playable game
- **GitHub Repository:** URL to your project repository
- **GitHub Wiki:** URL to your project wiki

Your GitHub Wiki must include:

- Completed **Creative Direction** section of the Concept Document
- **Gameplay Loop** documentation
- **Objects & Entities** documentation
- Completed **Asset List**
- **Class Diagram**

> [!Warning]
> **Your project cannot be graded if it is not accessible.** Your GitHub repository and Wiki must be in the **course organization**, and your itch.io game must be **publicly accessible and playable**.
